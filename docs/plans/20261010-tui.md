# Interface and rendering

[Roadmap](../roadmap.md) · Current task

## Goal

Prepare the terminal interface, editor, and streamed output before connecting real agents. A normal `clankr` launch uses the echo backend without authentication or network access. Mock model and skill catalogs exercise the real menus; submitted text streams back through the production Markdown renderer.

## Implemented

- [x] Multiline editor with shared grapheme/cell layout, word and line navigation/deletion, bracketed paste, and a viewport that keeps the cursor visible. Input is bounded to 1 MiB; control sequences from submitted text cannot execute in the terminal.
- [x] Separate submitted prompt and next draft. `Backend` reports waiting, generation, text, usage, completion, and errors without blocking input. Requests capture text, model/options, and selected skills; the next draft remains editable. One request runs at a time, response text is bounded to 16 MiB, and event batches are bounded.
- [x] Cancellation and exit behavior: Esc or Ctrl+C cancels an active request while preserving the next draft. When idle, Ctrl+C clears a nonempty draft and shows the repeat-to-exit hint; a new empty session exits immediately. Ctrl+D exits on empty input. Available terminal modes are restored on normal exit, handled errors, and panic.
- [x] Native wrapping and scrollback for messages, with normal mouse selection. Submitted text is bold and unprefixed; responses use normal text with Markdown. Faint lines frame the editor, and faint service messages use a two-column indent. Completed history is not redrawn; there is no alternate screen or mouse capture. Unsupported terminal resize behavior remains a manual compatibility check.
- [x] Submitted prompt history through Up/Down at document boundaries, preserving the new draft, cursor, Unicode, and picked skills. Enter during generation queues independent request snapshots in order; Up from an empty editor retrieves the last pending request for editing. Cancellation or failure pauses the queue until Enter; `/clear` discards pending requests.
- [x] Background for submitted user messages only, using a reserved palette entry through OSC 4. Query the terminal's foreground, background, and original slot; derive a subtle tint and confirm the write before using it. Recheck once per second so existing history follows theme changes without redrawing. Restore the original slot on normal exit, handled errors, and panic. Keep the editor unchanged and retain the original styling when queries are unsupported or `NO_COLOR` is set.
- [x] Separate `/` command and `$` skill menus with filtering, cyclic navigation, Right/Tab completion, and Esc dismissal. `/clear`, `/quit`, `/copy`, `/fast`, `/model`, and `/effort` work. Model changes preserve compatible effort; Ctrl+, / Ctrl+. adjust it independently. Skill and model catalogs remain mocks.
- [x] Streaming Markdown with an unfinished-block preview: headings, nested styles, lists, quotes, aligned tables with row separators, underlined clickable links, and fenced code blocks. `/copy` uses the original response. Code fences occupy separate lines so selecting a block body copies only code; unknown languages remain plain text.
- [x] Offline syntax highlighting through `syntect + Oniguruma + two-face`, retaining multiline state and classic terminal palette colors. The release binary is 3.20 MiB; measurements and the maintenance tradeoff are recorded below.
- [x] Formula rendering through `pulldown-latex` and `src/math.rs`: inline and block math, fractions, roots, matrices, aligned expressions, and limits. Unsupported notation remains readable as source. Markdown images display alt text/links; actual image attachments belong to future integration.
- [x] A single manual fixture, `mocks/markdown.md`, with `mocks/robot.svg`, covers Markdown, code, formulas, images, and multilingual text. Startup chooses a robot splash. Focused CLI checks use `uv run tests/cli.py --bin target/release/clankr --case <case>`.

- [x] Tables fit the current terminal width with one space of outer padding, balanced column widths, and word/grapheme wrapping inside cells. Alignment, styles, and links survive wrapping; quote/list indentation is included in the width budget. Extremely narrow tables become labelled cells. Pending tables reflow on resize without changing emitted content, including inside open containers.

## Known limits and deferred work

- OSC 4 changes a terminal-wide palette entry, including any other scrollback cells that already used slot 16. Restoring that entry at exit also changes the background of clankr's old user messages. Completed history is never rewritten to retain a custom colour after exit. Protocol: [XTerm control sequences](https://invisible-island.net/xterm/ctlseqs/ctlseqs.html#h2-Operating-System-Commands).
- Completed tables retain the layout used when emitted. Narrowing the terminal later can make those old rows wrap through native reflow; the application does not redraw scrollback. Pending and newly emitted tables use the current width.

- `mdtext 0.1.2` does not expose original fence lengths. Rendering always uses three backticks, so selecting an entire nested fenced example does not reproduce valid outer fences. Selecting code bodies and `/copy` remain available; keep this limitation within the interface task.
- The compact highlighting engine is integrated. Searching for a better maintained engine or a Rust implementation remains [deferred work within this task](#deferred-highlighting-follow-up).
- Real APIs, saved sessions, discovered skills, tool execution, and image attachments belong to the later tasks in the roadmap. Preserve the current backend boundary so those features can use this interface.

## Verification and stage boundary

For each selected change, use the existing focused Rust tests and the affected CLI scenario. Do not run every PTY case for an isolated renderer change. `make check` checks formatting and compilation; `make build` provides the normal executable for visual inspection. Run the full Rust suite when shared contracts change. The table-width fix passed all 67 Rust tests and the focused CLI Markdown check. A 42-column run of the normal CLI also confirmed multiline cell wrapping. The background change passed all 76 Rust tests, the CLI `theme` case with emulated OSC replies (3.08 seconds), and the ordinary `tui` case (20.65 seconds). These are recorded results, not proof of future changes.

Use `mocks/markdown.md` for visual checks of streaming, resizing, selection, and theme changes in the user's terminals. Physical keyboard shortcuts and the actual clipboard require manual checks; terminal emulation alone cannot establish them.

The outcome of this stage is a usable, independently verified TUI with predictable editor and rendering behavior on mock events. Connecting a provider should supply request events through `Backend`, while terminal input and rendering retain one owner. Select the integration stage separately after the interface work; do not start it as a side effect of a rendering fix.

## Decisions and measurements

### Syntax highlighting: selected solution

Use `syntect 5.3.0` with `parsing,regex-onig` and `two-face 0.5.2` with `syntect-onig`, both without default features. This replaces the separate Tree-sitter grammars with an offline catalog and resumable line parsing. The integration keeps the terminal palette and existing language aliases, including `shell` and `golang`.

Integration verified on 2026-10-10: the normal release CLI is 3,353,992 bytes (3.20 MiB), down from 20,205,592 bytes (19.27 MiB) with the same build profile. `make check test build` passed all 65 tests; the focused CLI `markdown` case passed in 4.13 seconds.

### Measurements and rejected alternatives

Research, 2026-10-09: built actual release CLI prototypes and a separate harness using the production Markdown/input/math code, changing only the highlighting adapter. The current `mocks/markdown.md` (SHA-256 `2e706ca2580f06b78b33e4dffce71f83f4bb3959f002a73e479697a2878232e0`) was streamed in 382 chunks of up to 16 graphemes. The latest comparison alternated three fresh processes per engine on macOS arm64. Time is the median first render; memory is the maximum first-render physical footprint from `proc_pid_rusage`, not RSS or the entire interactive CLI. Build settings were identical; mock delays and PTY tests were excluded.

| Engine | CLI binary | Renderer peak | First render |
| --- | ---: | ---: | ---: |
| Previous `tree-sitter-highlight 0.27.1` | 19.27 MiB | 20.75 MiB | 122 ms |
| `syntect 5.3.0` + Oniguruma + `two-face 0.5.2` | 3.20 MiB | 15.30 MiB | 71 ms |
| `giallo 0.5.2`, built-in registry | 3.92 MiB | 65.50 MiB | 182 ms |

- The original rejection concerned `syntect` with **`fancy-regex`**, which used approximately 161 MiB. Repeating that configuration on the current fixture gave a 4.37 MiB binary, 160.81 MiB memory, and 665 ms; limiting each delegated DFA cache to 64 KiB did not materially reduce memory. Neither the Oniguruma nor Giallo prototype requires a JavaScript/Wasm runtime; both link the native C regex library.
- The definitions themselves are compact: installed Sublime Text build 4215 contains 204 syntax files totaling 3.13 MiB, or 0.50 MiB compressed with gzip. `two-face` embeds approximately 0.91 MiB for fancy-regex or 0.94 MiB for Oniguruma. Data size alone does not predict runtime memory.
- `tree-sitter-language-pack 1.21.0` produced a 6.69 MiB binary but needed a 43.53 MiB fixture cache and 28.0 MiB renderer memory. Initial download/rendering took 9.9 seconds and peaked at 63.2 MiB. Cached offline rendering worked; TypeScript query inheritance and short language names needed fixes. Do not adopt that trial as-is.
- [Giallo](https://github.com/getzola/giallo) is an active TextMate alternative from Zola, with 132 stars and a default-branch commit on 2026-09-05 when checked. It was measured, not merely reviewed: its adapter retains and reprocesses the open block because the published API does not expose resumable tokenizer state. Its built-in registry used more memory than the Oniguruma/syntect candidate. Giallo's `onig-regset 6.7.0` and syntect's `onig 6.5.3` both depend on **`onig_sys 69.9.3`**, so switching to Giallo does not remove the underlying maintenance concern.
- [Oniguruma's C upstream ended on 2025-04-24](https://github.com/kkos/oniguruma). The Rust wrapper is not archived, but moving C-source maintenance into its fork remains tracked in [rust-onig #204](https://github.com/rust-onig/rust-onig/issues/204). This is the main tradeoff of the selected engine; a newer highlighter using the same core does not resolve it.

Compatibility: both final prototypes passed all 13 focused Markdown tests, including nested blocks, incomplete tokens, multiline strings/comments, aliases, palette styles, and streaming equivalence. In the research copy, the token-colour test checks the token's cells instead of an engine-specific surrounding span, and the Python string assertion permits a trailing newline in that span; checks were not skipped. All rendered fixture text matched the previous engine. The two syntect backends also produced identical final styled output. The integrated Oniguruma adapter uses the token-cell check and keeps the original multiline string assertions. Manual mouse-selection and cross-platform acceptance were not part of this investigation.

### Deferred highlighting follow-up

- [ ] Look for a better maintained compact engine, or assess a Rust implementation of Oniguruma-compatible matching. Compare binary size, memory, latency, and compatibility with existing syntax definitions before replacing it. Retain resumable streaming, offline use, aliases, and terminal palette colors. This research does not block the current TUI work.

### Formula rendering

Implemented with `pulldown-latex` and the terminal layout in `src/math.rs`; `mdtext` math events are enabled. Inline expressions, block fractions, roots, matrices, aligned expressions, and limits have text rendering. Unsupported or incomplete notation falls back to source text.

Earlier rejected options: a trial of [term-maths 1.0.0](https://docs.rs/term-maths/1.0.0/term_maths/) on 2026-10-09 showed that simple powers and fractions work, but `aligned` from `mocks/markdown.md` is truncated to `\begin{aligned} A`, and `\sqrt[3]{x}` becomes a square root with brackets. It was not adopted. `tui-math 0.1.1` was rejected because its required `ratatui 0.29` needs `unicode-width =0.2.0`, conflicting with the existing `unicode-width ^0.2.2`.
